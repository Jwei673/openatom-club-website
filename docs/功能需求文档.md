# 电子科技大学成都学院开放原子开源社团官网系统功能需求文档

版本：v0.1
项目类型：社团官网 + 内容社区 + 后台管理系统
技术方向：Vue 3 + Spring Boot 3 + PostgreSQL
后续兼容方向：OpenTenBase
文档状态：初始版，可后续补充修改

------

## 1. 项目背景

本项目为电子科技大学成都学院开放原子开源社团正式官网系统。

此前社团已举办“用 AI 做社团官网”比赛，比赛内容要求成员使用 AI 工具为开放原子开源社团制作官方网站，评分维度包括页面效果、页面功能、技术实现、AI 使用程度、可维护性与安全性、答辩表现等。

正式官网不应只是一个静态展示页，而应作为社团长期使用的线上平台，承担以下职责：

```text
对外：
展示社团形象、新闻动态、活动信息、项目成果、知识内容、加入方式。

对内：
支持成员登录、发帖交流、活动报名、项目参与、积分记录。

对管理者：
支持内容审核、用户管理、部门管理、权限管理、活动管理、项目管理、系统配置和操作日志。
```

------

## 2. 项目目标

本系统目标是建设一个长期可维护、可扩展、可部署的社团官网系统。

核心目标包括：

```text
1. 建立社团正式线上门户
2. 展示社团新闻、活动、项目和知识内容
3. 支持用户注册、登录和成员主页
4. 支持不同身份的权限管理
5. 支持帖子、评论、新闻、活动、项目等内容管理
6. 支持统一审批流和内容审核机制
7. 支持活动报名、签到和报名名单管理
8. 支持积分与贡献记录
9. 支持站内通知和后台待办
10. 支持后台管理、系统配置、操作日志和数据安全
```

------

## 3. 用户角色

系统包含以下用户身份：

```text
游客
成员
干事
部长
副会长
会长
```

### 3.1 游客

游客指未登录用户。

游客可以：

```text
浏览首页
浏览公开新闻
浏览公开活动
浏览公开项目
浏览知识库
浏览友情链接
查看加入我们页面
注册 / 登录
```

游客不可以：

```text
发帖
评论
报名活动
签到
进入后台
查看内部通知
查看个人中心
```

------

### 3.2 成员

成员指已注册并登录的普通社团成员。

成员可以：

```text
登录系统
修改个人资料
查看成员主页
发帖
评论
参与活动报名
活动签到
查看自己的积分记录
查看自己的站内通知
查看自己参与的项目
```

成员不可以：

```text
进入管理后台
发布新闻
审核内容
管理其他用户
管理部门
修改系统配置
查看操作日志
```

------

### 3.3 干事

干事指社团中承担具体工作的成员。

干事可以：

```text
进入后台
根据权限创建新闻草稿
根据权限创建活动内容
根据权限创建项目内容
查看与自己职责相关的后台模块
处理自己负责的内容
```

干事不一定拥有所有干事权限。
例如：

```text
宣传部干事可以写新闻
活动部干事可以管理活动
项目部干事可以维护项目内容
```

------

### 3.4 部长

部长指部门负责人。

部长可以：

```text
管理本部门成员
管理本部门干事
审核本部门相关内容
发布或审核新闻、活动、项目
查看本部门数据
处理后台待办事项
```

部长默认只能管理本部门范围内的数据。

------

### 3.5 副会长

副会长属于社团高级管理者。

副会长可以：

```text
管理部长
管理多个部门
审核重要内容
查看全站后台数据
处理跨部门事务
查看操作日志
管理大部分内容
```

副会长不能随意管理会长权限。

------

### 3.6 会长

会长为系统最高管理者。

会长可以：

```text
管理所有用户
管理副会长
管理部长
管理部门
管理权限
管理系统配置
查看操作日志
处理所有后台事务
```

# 二、用户与组织

用户可以通过注册成为系统成员。

注册字段包括：

```text
用户名
邮箱
密码
确认密码
昵称
```

可选字段包括：

```text
真实姓名
学号
专业
年级
手机号
```

```text
注册后默认身份为成员

邮箱或用户名不能重复
可通过系统配置控制是否开放注册
```

------

用户可以使用账号登录系统。

登录方式：

```text
用户名 + 密码
```

```text
返回 JWT
记录最后登录时间
```

登录失败应有明确提示。

# 三、权限与审批

## 7. 权限与审批模块

权限与审批模块用于控制用户能做什么，以及内容是否可以发布。

### 7.1 角色权限

系统采用：

```text
RBAC + 权限点 + 数据范围
```

角色包括：

```text
游客
成员
干事
部长
副会长
会长
```

权限点示例：

```text
post:create
post:review
news:create
news:publish
activity:create
activity:manage
project:create
project:manage
user:manage_member
user:manage_officer
user:manage_minister
department:manage
system:settings
audit:view
```

数据范围包括：

```text
self：只能管理自己
department：只能管理本部门
all：可以管理全站
```

------

### 7.2 角色继承

角色存在等级关系：

```text
游客 < 成员 < 干事 < 部长 < 副会长 < 会长
```

但系统不能只依赖等级判断权限。
必须结合：

```text
角色等级
权限点
数据范围
```

例如：

```text
部长可以管理本部门成员和干事
副会长可以管理部长
会长可以管理副会长
```

------

### 7.3 统一审批流

系统支持统一审批流。

审批对象包括：

```text
帖子
新闻
活动
项目
系统配置，可选
```

审批状态包括：

```text
待审核
已通过
已驳回
已取消
```

审批流程：

```text
用户提交内容
系统生成审批记录
审核人查看待审核内容
审核人通过或驳回
系统更新内容状态
系统发送站内通知
系统写入操作日志
```

# 20. 功能验收标准

系统第一版完成后，应满足以下验收标准。

## 20.1 游客验收

```text
可以访问首页
可以查看新闻
可以查看活动
可以查看项目
可以查看加入我们
不能发帖
不能报名
不能访问后台
```

------

## 20.2 成员验收

```text
可以注册
可以登录
可以修改个人资料
可以发帖
可以评论
可以报名活动
可以签到
可以查看积分
可以查看通知
不能进入后台
```

------

## 20.3 干事验收

```text
可以进入后台
可以根据权限创建新闻、活动或项目
不能随意管理用户
不能越权管理部门
```

------

## 20.4 部长验收

```text
可以管理本部门成员和干事
可以审核内容
可以发布本部门相关内容
不能管理其他部门部长
```

------

## 20.5 副会长验收

```text
可以管理部长
可以查看全站内容
可以处理跨部门内容
不能随意替代会长最高权限
```

------

## 20.6 会长验收

```text
可以管理所有用户
可以管理副会长
可以管理部长
可以管理权限
可以管理系统配置
可以查看操作日志
```
